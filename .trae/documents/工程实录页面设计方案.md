# 「AI 协作工程实录」页面设计与实现方案

## Context

首页「站点导览」原有一条「笔记 / Notes」，长期停留在「即将上线」占位。用户最初考虑把两个项目仓库里的学习文档（ForgeAI：33 篇会话记录 + 阶段复盘 + 21 篇 ADR；HengPick：14 篇学习笔记）整理成笔记列表，但最终否掉了这个方案：

**不做笔记列表，改为一个单页「工程实录」**，从首页直接进入，唯一目标是向面试官展示「AI 协作编码的工程能力」——因为在当前的求职市场里，会用 AI 已经不是加分项，用好 AI 才是。

两条来自用户的明确约束：

- 日常 AI 工具是 **TraeCode**（负责日常开发）与 **Codex**（负责复杂任务）。
- 页面设计交由我完成，内容可参考两个项目的真实沉淀并适当发挥。

页面内容的事实来源全部可追溯，不需要编造：ForgeAI 的 `AGENTS.md`、`docs/context/INDEX.md`、`docs/learning/` 下的会话记录与阶段复盘、`docs/adr/`；HengPick 的 `docs/learning-notes/`。

## 目标产物

- 新增路由 `/engineering`，一个纸面编辑风长页（与 `/resume`、`/projects` 同一视觉气质）。
- 首页「站点导览」第 3 条从「笔记 / Notes」改为「工程实录 / Engineering」，可点击进入。

## 视觉与交互基调

沿用 [ResumeView.vue](file:///Users/ruicheng/Documents/code/personal-static-web/src/views/ResumeView.vue) 的既有范式，不引入新的设计语言：

- 顶栏下方 2px 阅读进度条（`scaleX` 绑定滚动比例）
- sticky 页内目录，滚动时高亮当前分节
- 每节带锚点 + `scroll-mt-[calc(var(--topbar-h)+3.5rem)]`
- 复用 `v-reveal` 入场、`v-scramble` 编号乱序、`main.css` 的 `wrap` / `eyebrow` / `mono` / `btn` 工具类
- 文本用 `**加粗**` / `==强调==` 标记，由组件内 `rich()` helper 解析（与 `resume.js` 一致）

非沉浸式布局：不走 `meta.immersive`，因此 [App.vue](file:///Users/ruicheng/Documents/code/personal-static-web/src/App.vue) 无需改动，顶栏与页脚自动保留。

## 内容骨架

Hero：编号 `03`、标题「工程实录 / Engineering」、英文斜体 lede、一段导语，右侧用数据条呈现真实数字——**33 次会话 / 7 个阶段 / 21 篇 ADR / 2 个已部署项目**。

| # | 分节 | 核心论点 | 真实素材 |
|---|---|---|---|
| 01 | 我的判断 | AI 能把代码写出来，但不会替你做判断。交付质量由四件事决定：上下文给多少、边界划在哪、怎么验证、什么时候不接受它的结论 | 两个项目的共同结论 |
| 02 | 上下文路由 | 不给 AI 通读文档。写了 `AGENTS.md` 定架构与安全边界，再用一份 `docs/context/INDEX.md` 把 33 次会话各自映射到最小必读章节；默认不通读任何基线文档，只有索引覆盖不到、命中章节冲突、要求全局评审、需要改架构基线时才扩大读取 | `AGENTS.md`、`docs/context/INDEX.md` |
| 03 | 阶段边界 | 不提前实现下一轮。项目拆成 P0–P6 七个阶段，一次会话只做一件事；执行纪律包括分小步实现、每个逻辑单元跑对应测试、不吞失败、不用 mock 掩盖本轮核心规则、发现跨阶段问题记为遗留项、阶段内不跑全量 CI 留到复盘统一跑 | `docs/learning/temp.md` |
| 04 | 让规则可执行 | 写进文档的规范会被忽略，写进测试的才会被遵守。`ModuleArchitectureTest` 带故意违规的 fixture，证明规则真的能失败；契约 schema 把权限、风险等级、幂等、超时、重试写成必填，Skill 不得引用不存在的 Tool；部署拓扑也进测试，解析最终 Compose 检查唯一入口、内部网络与凭据边界 | 阶段复盘 P0、`tool-contract.schema.json` |
| 05 | 把 AI 的输出当意图 | 模型提出操作，服务端决定能否执行。Python 只表达业务意图，金额、报价与最终评分来自 Java 确定性边界；结构化输出走「模型输出 → 校验 → 最多一次修复 → 显式规则降级」；最终发布属 HIGH 风险，忽略 Run 策略无条件走他人独立审批，恢复时重校验权限、TTL、工具版本与参数 hash | ADR-002、会话 22/31、HengPick P10 |
| 06 | 复盘机制 | 让 AI 反过来考核我。每次会话产出一份学习文档，每阶段做一次复盘，提示词明确要求「先让我回答再按代码评价、不要泛泛复述技术栈、不要直接给出答案」；产出是一条真实请求链路、三个不变量及其保护代码、三个故障追问、一个「值得改进但现在不应过度设计」的点 | 阶段复盘 P0/P1、`temp.md` |
| 07 | 工具 | TraeCode 负责日常开发，Codex 负责复杂任务。工具换来换去不是能力，能不能把边界和验证固化下来才是 | 用户口述 |
| 08 | 成果与边界 | 也说没做完的部分。发布执行器目前是模拟部署；权限查询实时查 MySQL 未加版本失效缓存；OpenAPI Client 生成仍是占位；worker 崩溃后的租约回收未做。能说清「哪里没做完、为什么现在不做」，比列一堆功能更能说明判断力 | 会话 31 遗留问题、阶段复盘 |

结尾：CTA 指向两个项目详情、简历与联系方式。

## 实现步骤

1. **新增 `src/data/engineering.js`**
   导出 `engineering` 对象，结构对齐 `resume.js`：`hero`（eyebrow / title / en / lede / intro / stats）+ `sections[]`（`id` / `num` / `title` / `en` / `paras[]` / `points[]`）。文案用 `**加粗**` / `==强调==` 标记，文件头注释说明标记约定（照 `resume.js` 第 1 行的写法）。

2. **新增 `src/views/EngineeringView.vue`**
   照抄 `ResumeView.vue` 的骨架：`measure()` / `onScroll()` / `queued` 的 rAF 节流滚动监听、`active` 分节高亮、`rich()` 富文本解析、`onMounted` / `onBeforeUnmount` 事件注册与解绑。模板部分为阅读进度条 + sticky 页内目录 + hero + `v-for` 渲染分节 + 结尾 CTA。尽量只用 Tailwind 工具类与 `main.css` 现有类，**不改 `main.css`**；如确有需要，再在 `main.css` 的 `@layer components` 内加一小段 `.eng-*` 规则。

3. **修改 `src/router/index.js`**
   在 `/projects` 之后插入 `/engineering`：懒加载 `@/views/EngineeringView.vue`，`name: 'engineering'`，`meta.title: '工程实录 · AI 协作 — YJX'`。不加 `immersive`。`scrollBehavior` 与 `afterEach` 复用现有实现，无需改动。

4. **修改 `src/data/site.js`**
   把 `navIndex` 第 3 条从「笔记 / Notes」改为「工程实录 / Engineering」：`to: '/engineering'`、`domain: 'yjxai.cloud/engineering'`、`tags: ['AI 协作', '工程方法']`，删除 `soon: true`。`num` 保持 `'03'`。

5. **修改 `index.html`**
   在 `meta description` 与 `og:description` 里补一句「AI 协作工程实录」，并更新文件顶部「需要替换的内容」注释中的路由列表（加 `/engineering`）。
